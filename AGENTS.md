# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this project is
PyRaya (پیرایہ) is a **reusable, self-contained PySide6 (Qt) text editor widget** for Urdu / Nastaliq (right-to-left) text. It is a drop-in `QWidget` for embedding Urdu text editing in Qt applications — currently PySide6 only.

Current status: **alpha (0.1.0-alpha.5)**. The widget is a `QPlainTextEdit` with RTL layout, right-aligned paragraphs, a configurable Noto font stack (default `Noto Naskh Arabic`), visible whitespace, a dedicated rule-based formatting highlighter, and text regions implemented: spans tagged as `latin` or `roman urdu` (:class:`RegionType`) and rendered with a subtle, type-specific background color, tagged from the right-click context menu, the `Ctrl+1` / `Ctrl+2` keyboard shortcuts, or `setRegionType`. Every character belongs to exactly one region kind at all times — untagged text belongs to `defaultRegionKind` (RomanUrdu) — each kind's identity is its unique background color (compared including the alpha channel), and clearing regions resets the text to `defaultRegionKind`. A **roman-input overlay** is also implemented and is enabled by default (`setRomanInputEnabled`): an Arabic-script word inside a `roman urdu` region gets a small frameless, non-modal overlay `QLineEdit` matched to the word's geometry — typed roman text is edited there while the document stays Arabic-script, a tier-colored suggestion list (green = exact, orange = edit-distance 1, red = distance 2) is offered below (at most five rows, scrolling so the highlighted row stays visible), and committing (Space / Enter / typed punctuation, or Left/Right at the word's text edges) writes the selected Arabic word plus the separator character to the document tagged as `roman urdu` (a plain Enter commits the word plus a newline; Ctrl+Enter commits the word without one); an edge commit (Left at the visually left edge of the word, Right at the visually right edge) writes nothing and moves the cursor in visual order — to the next word or the previous one — hiding the overlay when there is no adjacent word. The overlay is placed in viewport coordinates and re-anchored on widget resize (`PyRaya.resizeEvent`): a resize reflows the right-aligned document without moving the cursor or editing it, so the active overlay is re-placed from its stored anchor (the word's rect, or the seeded cursor anchor) after the base handler updates the viewport and text layout, without re-evaluating activation. Zero-match typed words get a `+ Learn <word>` undefined-word row whose commit is a session no-op that writes the typed roman word. Plain Left/Right arrow keys in the document move the cursor in visual (screen) order, since Qt's default logical movement is flipped in this RTL document; modifier variants keep the logical behavior. The engine wraps `romanalfaz`'s `RomanAlfaz` and `romanWordCommitted` signals each committed word. Assist mode is on by default as well: typing and cursor movement activate the overlay as described; Esc on an active overlay dismisses it and turns assist mode off (the user is left alone: typing and mouse presses no longer activate the overlay) until `Ctrl+Space` in the document turns it back on — over the `roman urdu` word under the cursor with its romanized text, or, with no such word, an empty overlay at the cursor; committing never turns the mode off, and Esc in the document (overlay inactive) is a no-op. `setAssistEnabled(False)` hides a shown overlay, `setAssistEnabled(True)` only marks the mode ready, and re-enabling the feature (`setRomanInputEnabled(True)`) resets assist mode to on. The built-in spell-checker remains on the **roadmap** (see `README.md`) and is *not yet implemented*. Do not assume it works.

## Conventions
- Use the `src/` layout. The importable package is `pyraya` — import from `pyraya`, **not** `src.pyraya`.
- Naming follows the Qt toolkit: `camelCase` for variables, functions, methods, and signals; `PascalCase` for classes and enum members.
- Type hints are required on public functions and classes; the whole project must pass `pyrefly check`.
- Public API must have docstrings (Google-style sections such as `Args:`, with reST cross-references like `:class:`).
- New public symbols must be re-exported from `pyraya/__init__.py` and added to `__all__`.
- New source modules include the copyright banner header used in `pyraya_widget.py`.
- Keep lines within ruff's 100-character limit.
- Keep `ruff check`, `ruff format`, and `pyrefly check` clean before considering work done.
- Keep imports sorted and minimal (ruff `I`).
- Do not add third-party dependencies without updating `pyproject.toml` and re-locking (`uv lock` / `uv sync`).
- Version bumps: change `version` in `pyproject.toml`, run `uv lock`, and update the version string in `README.md`.

## Testing
- This is a **GUI** app. Automated checks must run headless — use the offscreen Qt platform so tests do not open a window. The test sets `QT_QPA_PLATFORM=offscreen`.
- The suite instantiates `PyRaya` under an offscreen `QApplication` and covers widget defaults plus the text-region API (tagging, span reconstruction, persistence through edits and undo/redo, popup-menu actions, keyboard shortcuts, the custom-context-menu trigger, the `regionsChanged` signal contract, and undo/redo cleanliness — no phantom command on a fresh widget, no undo/redo ping-pong).
- A second suite (`tests/test_roman_input.py`) covers the roman-input overlay: the engine's suggestion tiers, undefined-word rows, and `available` flag; the overlay widgets (suggestion list selection, key handling, visible-row scrolling, wheel forwarding); overlay activation over `roman urdu` words and keystroke activation of new words; and the commit matrix — separator (a plain Enter commits the word plus a newline; Ctrl+Enter commits the word without one), edge, undefined-word, and empty-text commits with region tagging, signal contracts, and undo/redo cleanliness — plus plain Left/Right visual-order cursor movement in the document, and mouse/overlay differentiation — the mouse-transparent overlay and line edit, press ownership with release resync, drag, shift-drag, and double-click selection, `_syncOverlay` suppression while the mouse is active, and the post-commit resync that bypasses the mouse flag — and resize re-anchoring: a widget resize reflows the right-aligned document without a cursor move or document edit, so `PyRaya.resizeEvent` re-places the active overlay from its stored anchor (the word's rect in scenario 2, the seeded cursor anchor in scenario 1) after the base handler updates the viewport and text layout, without re-evaluating activation (which would clobber the typed text or deactivate the overlay), and the assist-mode contract: on by default, Esc on the active overlay turns it off, typing and a mouse release do not reactivate it while off, Ctrl+Space re-enters the mode (over the word under the cursor, or an empty overlay at the cursor), commits and a document-level Esc never flip the flag, `setAssistEnabled` hides a shown overlay but re-enabling only marks the mode ready, re-enabling the feature resets the mode to on, and second-block geometry: typing in the second paragraph after an Enter commit seeds and commits the overlay in the second block without a crash, and the word rect and cursor anchor over a second-block word agree with Qt's own viewport-coordinate cursor mapping (`cursorRect`), including scenario-2 re-activation on a mouse release over the word.
- New tests must reuse the single offscreen `QApplication` (see the `app` fixture); never call `QApplication.exec()` inside a test.

## Gotchas
- Instantiating `PyRaya` requires a `QApplication` to exist (see the offscreen test).
- The **Noto** fonts (Noto Naskh Arabic, Noto Nastaliq Urdu, Noto Sans Arabic, …) may not be installed in CI / agent environments — the widget falls back through its font stack and lets Qt substitute; do not assume a specific font is available in automated tests.
- RTL layout is implemented via the widget layout direction and right-aligned blocks; the shaping engine handles Urdu/Arabic script ordering. The Noto fonts may be absent in automated environments, so the rendered font may be a fallback.
- `pydantic` is a declared dependency but is currently unused — reserved for roadmap work; do not build the current API on it. `romanalfaz` backs the roman-input engine: `RomanAlfaz()` must be constructed before calling `addVocabulary`, and `suggest()` returns a **list of per-tier lists**, not a flat list.
- **Never stage IDE/editor files** — `.idea/`, `.vscode/`, and other IDE-specific files are git-ignored and must not be committed.
- Do not hand-edit `uv.lock` — regenerate it with `uv lock`.
- The demo (`uv run pyraya`) opens a real window; automated verification stays limited to the offscreen test suite.
- Qt documents keep an implicit trailing terminator character, so `characterCount()` is one greater than the visible text length. Character-format merges spanning that character are silently dropped — region ranges are clamped to `characterCount() - 1`, and the region lookup for the right-click context menu guards the same boundary, so a right-click on an empty document, or with the cursor at the end of the text, never requests an out-of-range `QTextCursor` position; the scenario-1 typing gate (`_regionKindForTyping`) deliberately admits the document-end position, resolving to the kind of the last real character before the cursor (or `defaultRegionKind` on an empty document). Region state lives in the document's character formats (background colors), which is why spans survive edits and undo/redo; cleared characters are repainted with the `defaultRegionKind` background color because a merge cannot restore a `NoBrush` background.
- `QSyntaxHighlighter.setFormat` applies formats to the text **layout**, which Qt merges with the document's character formats at display time — it never modifies the document's character formats (invisible to `QTextCursor.charFormat()` and `QTextBlock.charFormat()`), is re-applied on every re-highlight, and is never recorded in the undo stack. The highlighter's region-maintenance pass therefore only paints the `defaultRegionKind` background into the layout for untagged runs; region state itself is stored in the document's character formats (cursor merges). `QSyntaxHighlighter.currentBlock()` is the block accessor in Qt 6 (`current()` does not exist).
- Never make a repaint in response to a document change undoable: undoing it exposes untagged text, the repaint pushes a new command, and Qt clears the redo stack on any new edit, so the original edit becomes unreachable behind an undo/redo ping-pong. The initial block-alignment merge in `__init__` is wrapped in `document().setUndoRedoEnabled(False)` / `(True)` so a fresh widget has no phantom undo command; Qt's `setPlainText` replacement is likewise not recorded in the undo stack.
- PySide6 does not dispatch `QWidget.createPopupMenu` or `QWidget.contextMenuEvent` to Python overrides on `QPlainTextEdit` subclasses (both work only on plain `QWidget`), and does not expose `QClipboard.hasText`. The context menu is therefore handled by connecting to `QAbstractScrollArea.customContextMenuRequested` — emitted by the scroll area's viewport event filter when the policy is `CustomContextMenu` (set in the constructor, which also suppresses Qt's automatic empty popup). The request position arrives in viewport coordinates and is converted with `viewport().mapToGlobal()`. The menu is built on `createStandardContextMenu()` plus the region actions. `QTextCursor.MoveMode.KeepAnchor` is the stub-correct spelling.
- PySide6 delivers the widget-level `QPlainTextEdit.cursorPositionChanged` signal to Python slots **without the int argument** — overlay-sync slots must be argument-free; the document-level `cursorPositionChanged` never fires on cursor moves, and `contentsChanged` fires on typing.
- `QTextLine.cursorToX(pos)` returns a plain `(x, y)` tuple in PySide6, and `contentOffset().x()/.y()` are floats — round the whole sum (`round(left + offset.x())`) rather than `int(round(x))` to keep pyrefly quiet.
- `QTextLayout.lineForTextPosition(pos)` and `QTextLine.cursorToX(pos)` take **block-local** positions (`0 <= pos <= len(block.text())` — the block text excludes the terminator), not absolute document positions: an absolute position overflows the block's own layout past block 0 (where absolute == local by coincidence), and the engine returns an **invalid `QTextLine`** (null engine, index −1) that PySide6 wraps as **non-`None`** — so an `is None` guard is dead code; the correct guard is `line.isValid()`, and calling `rect()` / `cursorToX()` on an invalid line segfaults (the paragraph-2 crash). Line geometry is **layout-local**: `line.rect().top()` is 0 for the first line of *every* block, `block.layout().position()` is `(0, 0)`, and the `cursorToX` tuple's y is the line's layout-local y — the block's y in the document is not stored in the layout; it comes from `blockBoundingGeometry(block)` in content coordinates and must be added to the line's top before translating with `contentOffset()` into viewport coordinates (Qt's own `cursorForPosition` / `cursorRect` follow this exact model, and `QPlainTextEdit.cursorRect` returns the rect in viewport coordinates — the cross-check used by the second-block geometry tests).
- Wheel events do not bubble from the overlay line edit to the host scroll area: the overlay forwards wheel events directly to the nearest `QAbstractScrollArea` ancestor's `wheelEvent`.
- Character formats on block-terminator characters (an internal `\n` **and** the trailing document terminator) are silently dropped — so the newline separator of an Enter commit stays untagged (default kind). A span-replacement commit via `insertText` on a selection is counted by `availableUndoSteps()` as two steps (delete + insert) but is undone and redone as a single logical edit; the widget cursor does not follow a document-cursor edit, so a commit calls `setTextCursor(cursor)` explicitly.
- PySide6 cannot map `Suggestion | None` as a `Signal` argument type — the overlay's `committed` signal is declared `Signal(str, object, int, str, int)`, and handlers narrow the second argument with `isinstance(..., Suggestion)`.
- Only `RomanOverlay.setText(roman)` (and key input) refreshes the suggestion rows; raw `overlay.lineEdit().setText(...)` leaves the rows stale. `RomanInputEngine.suggestTiers` returns empty when the engine is unavailable (`available` is False, e.g. `DictionaryNotFoundError` during construction; cold engine load is ~0.2 s).
- The roman-input feature is on by default: an ASCII alphanumeric key pressed with the cursor inside a `roman urdu` region (which includes all untagged text) seeds the overlay and never reaches the document; with the feature disabled (`setRomanInputEnabled(False)`), roman keystrokes type straight into the document and no overlay machinery runs. Assist mode is likewise on by default, and only `_onOverlayCanceled` (the `RomanOverlay.canceled` handler) turns it off — commits and cursor-driven deactivation leave it on — with the gate in two places: the typing-seed condition in `keyPressEvent` (`and self._assistMode`) and the `_syncOverlay` early return (`or not self._assistMode`). `Ctrl+Space` in the document's `keyPressEvent` sets the flag back on and activates the overlay (over the word under the cursor via `_activateOverlay`, or at the cursor via `_activateOverlayAt` with empty text); both flags off means no overlay machinery.
- Qt's default Left/Right arrow keys move in **logical** character order (Left = position−1, Right = position+1), which is visually flipped in this right-to-left document. The widget therefore intercepts plain Left/Right (no modifiers) in `keyPressEvent` and moves the cursor in visual (screen) order — Left advances the position, Right retreats it — clamped to `characterCount() - 1`; Ctrl/Shift variants fall through to Qt's logical default.
- The overlay's roman word renders in **left-to-right character order** even though the overlay widget is right-to-left laid out and right-aligned (the line only grows leftward as it is typed): position 0 is the visually left edge and the text end the visually right edge. So the line edit's Qt-default in-text Left/Right are already visually correct, and its edge-commit triggers stay Left at position 0 / Right at the text end; only the commit target is visual-order — Left at the visually left edge moves to the **next** word, Right at the visually right edge to the **previous** one, and with no adjacent word the overlay hides with the cursor at the word's visually left edge (outside the word, so the overlay does not re-activate on the next key press).
- The host re-places the overlay on every line-edit `textChanged` (`_onOverlayTextChanged`), so its width tracks the typed text: `RomanLineEdit.sizeHint` is the text advance plus the 6 px margin per side (matching the `SuggestionList` margin convention), and `_placeOverlay` takes the wider of that and the activation width floor — the word's rect width in scenario 2 (the overlay is never narrower than the Arabic word it covers), or the four-roman-character baseline (`4 * lineEdit.fontMetrics().averageCharWidth()`) for a seeded overlay with no word — so the left edge walks with the text while the right edge and top stay pinned at the activation anchor; the height is still fixed at activation. `_syncOverlay` never re-runs while the user edits in the overlay (the document cursor and contents are untouched). When the suggestion list's row count or visibility changes during editing, the overlay's `QVBoxLayout` redistributes the leftover vertical space — QBoxLayout splits it evenly across the layout gaps, which drags the `RomanLineEdit` down away from its top anchor (visible at a two-character text, and when the text is empty and the list hides). The overlay's trailing `layout.addStretch()` absorbs all leftover space so the line edit stays pinned to the overlay's top at all times; removing it regresses the drift.
- `RomanOverlay` and `RomanLineEdit` are both mouse-transparent (`Qt.WA_TransparentForMouseEvents`), so `QApplication.widgetAt` over the word returns the document viewport — the document receives real presses, and drags and double-clicks run their default selection; keyboard focus is independent of hit-testing, so the host still calls `setFocus` on the overlay line edit at activation. `PyRaya.mousePressEvent` deactivates the overlay and then sets `_mouseActive`, so `_syncOverlay` early-returns while the button is down (a drag would otherwise reposition the overlay mid-drag, and cross-boundary deactivation would refocus the document); `mouseReleaseEvent` clears the flag after default handling and resyncs — a release on a `roman urdu` word re-activates the overlay (scenario 2) with line-edit focus. The post-commit resync passes `bypassMouse=True`, so the edge-commit cursor jump is still reconciled while the flag is set. Press-point quirk — a press at `_wordRect(...).right()` (1 px inside the exclusive right edge) lands the cursor inside the word (at its start), a press at the visual center of a short word lands after the word (on the trailing space, no overlay), and a release at `_wordRect(...).left() + 1` lands at the word's end.
