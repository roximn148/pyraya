# Step 2: PySide6 6.12.0

**Plan:** agreed in conversation on 2026-11-04 (no separate spec file); authority is
the agreed step-2 plan plus the AGENTS.md conventions.
**Goal:** bump PySide6 from 6.11.2 to 6.12.0 — one step, kept separate from step 1
(Python 3.13 + romanalfaz a11 + pydantic removal, commit `c683ca4`) for failure
attribution.
**Verification:** the repo's own gate — `uv run pytest`,
`PYRAYA_LATENCY=1 uv run pytest -s`, `uv run ruff check`, `uv run pyrefly check`.

## Context

- This branch is based on step 1's HEAD (`c683ca4`), so its tree is the actual
  final state: Python 3.13 + romanalfaz a11 + no pydantic + PySide6 6.12.0.
  Step 2's commit is purely the PySide6 bump.
- PySide6 6.12.0 metadata (verified): `requires_python >=3.10,<3.16` (compatible
  with the 3.13 baseline); cp310-abi3 wheels (interpreter-independent); uploaded
  2026-10-08.
- The 6.11.3 / 6.12.0 changelogs are NOT verifiable from an authoritative source
  — treat as open. The step-2 risk seams are the AGENTS.md behavioral gotchas
  that the suite pins: block `charFormat` staleness, `rehighlight()`'s
  revision bump, `QDialogButtonBox` wiring (the "In PySide6 6.11.2 the box's
  automatic connection to the parent QDialog's accept()/reject() does not fire"
  note), and the `cursorRect` / `QTextLine` geometry model. 6.12 also ships
  refreshed `.pyi` stubs, which can shift `pyrefly` results.
- Floor decision: raise `pyside6>=6.11.2` to `pyside6>=6.12.0` — we test and ship
  on 6.12.0, so we require at least 6.12.0.
- Unlike step 1 (pure config), a dependency bump has a real behavioral risk that
  the suite is the authoritative check for: if a pinned behavior changed in 6.12.0,
  the suite catches it, and that is a genuine step-2 finding (systematic-debugging,
  rule, ledger) — not a config-file exception.
